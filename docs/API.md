# AdaptCode — Backend API Surface

> Ground-truth reference of every FastAPI route the backend exposes.
> Generated by reading the routers directly (`backend/app/routers/*.py`).
> If this diverges from code, **code wins** — fix this file.

## Core problem flow (`/api`)

| Method | Path | Auth | Notes |
|---|---|---|---|
| `POST` | `/api/start` | cookie | Marks problem as in-progress for timer; upserts `active_problem_state`. |
| `POST` | `/api/submit` | cookie (20/min) | Full pipeline: Piston exec → BKT update → LinUCB → session_event insert → background Gemini on failure. Returns `{verdict, test_cases_passed/total, mastery, next_problem, effective_weight, explanation_status, event_id}`. |
| `POST` | `/api/abandon` | cookie | Records abandonment, applies w=0 BKT penalty. |
| `GET` | `/api/explanation/{event_id}` | cookie | Polls for the Gemini explanation written by the submit's background task. `{status: pending|completed|failed, what_went_wrong, why_approach_fails, concept_to_review}`. |
| `GET` | `/api/next-problem` | cookie | Picks weakest unlocked concept → LinUCB action → unsolved problem. Returns `{id, title, concept, difficulty}` **plus maybe `hint_pre_expanded`**. |
| `GET` | `/api/diagnostic` | cookie | 10 seeded problems across the fundamental concepts for cold-start onboarding. |
| `GET` | `/api/problems` | — (admin client) | Lists catalogue; dedupes by title. |
| `GET` | `/api/problems/{problem_id}` | cookie | Full problem; **hidden test cases stripped server-side**. Accepts slug or UUID. |
| `GET` | `/api/problem/potd` | cookie | Deterministic daily problem (hash of UTC date). |

### Problem-id resolution

The database keys problems by `uuid`. The frontend uses slugs (`two-sum`). Both `/api/submit`, `/api/start`, `/api/abandon`, and `/api/problems/{id}` accept either — slugs are converted to `uuid5(DNS, "adaptcode.problem.<slug>")` by `_resolve_problem_id` in [problems.py:70](../backend/app/routers/problems.py).

## Known issues (as of 2026-11-08)

- **TEST_MODE auth bypass** (see [security/SECURITY_ISSUES.md](../security/SECURITY_ISSUES.md) C1): if `TEST_MODE=true` in prod, `DEV_TOKEN_<email>` grants that user's session with no password. The `main.py` guard is an `assert` — stripped under `python -O`. Must be removed before production launch. Scheduled for Phase C.
- **`/api/checkout/mock-upgrade`** gates on `require_admin` but `is_pro` is a per-user flag — intent was probably per-user admin self-promotion for testing. Review before prod.
- **`/api/leaderboard`** was broken on `main` through 2026-11-08 (referenced undefined `user` variable). Fixed in commit following this doc.
